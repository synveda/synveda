Synveda is a self-hosted memory and context control plane. Bring knowledge, reusable skills and tool definitions into one place, with policy and review built in.

A shared foundation

Useful context.
Durable knowledge.

Keep what agents learn separate from what they are allowed to use. Synveda connects the two through explicit scope, policy and provenance.

Context

Compose a token-budgeted context block from policy-visible knowledge and authored context. Inspect the selected revisions and reasons.

Knowledge

Retain facts, decisions and conventions as immutable revisions. Trace their sources, review new learnings and query past states.

Skills

Review versioned skill bundles, then bind exact versions to a project or principal. Supported adapters resolve the approved files.

Tools

Govern MCP server definitions and project bindings. Catalogue and discovery stay separate from tool execution in the agent’s environment.

Trust is part of the architecture

Learning is a proposal.
Publishing is a decision.

Sessions record agent activity. Capture turns selected evidence into reviewable candidates. A typed VedaFlow change governs publication as Knowledge.

Every application read and write passes through the embedded Cedar policy engine. PostgreSQL forced row-level security backs tenant isolation, and the audit chain keeps content-minimised evidence.

Start with the local demo

See the whole
context loop.

Run the Docker Compose stack, sign in and create your workspace. The optional Northstar walkthrough uses synthetic data to demonstrate capture, review, Knowledge and context.

For local evaluation. Production release, recovery, key custody and availability gaps remain. Read the current assessment.

01

Prepare your host

Docker Engine 28+, Compose 2.33.1+, local Buildx, Node 22+, OpenSSL and Make. Review the local hostname setup first.

Follow the complete quick start ↗
02

Start and verify

From the checkout, after completing the hostname prerequisites: 

export SYNVEDA_COMPOSE_PROFILES=demo
make compose-config
make compose-up
make compose-smoke
03

Sign in and explore

Open the printed console URL. Use the generated local demo credentials, then follow the workspace onboarding or the governed review walkthrough.

Stop with make compose-down using the same selectors. Data and generated secrets are preserved.

The normal Job {{ include "synveda.fullname" . }}-install-{{ .Release.Revision }}
performs bounded preflight, advisory-locked migration and optional idempotent
admission. Gateway and worker receive only their own non-owner database Secrets.

  kubectl --context "$CONTEXT" -n {{ .Release.Namespace }} logs job/{{ include "synveda.fullname" . }}-install-{{ .Release.Revision }} -c database-preflight
  kubectl --context "$CONTEXT" -n {{ .Release.Namespace }} logs job/{{ include "synveda.fullname" . }}-install-{{ .Release.Revision }} -c migrate

Register exactly {{ .Values.gateway.publicUrl }}/auth/callback with the issuer
in {{ .Values.oidc.existingSecret }}. Its static tenant ID must match
install.tenant.id, or an already-admitted operator-managed tenant.
External login alone grants no workspace membership. Use the existing first
administrator group, then public API invitations and governed grants.

Secrets are mounted files and are never generated or printed by this chart.
After externally rotating credentials or CA files, roll the affected process:

  kubectl --context "$CONTEXT" -n {{ .Release.Namespace }} rollout restart deployment/{{ include "synveda.fullname" . }} deployment/{{ include "synveda.fullname" . }}-worker

Back up {{ .Values.kms.existingSecret }} separately from the database. Replacing
a KMS Secret is not a key-rotation ceremony. See deploy/helm/synveda/README.md.

Both processes use Recreate: upgrades interrupt service. Local qualification
is recorded separately from published artifacts. No gateway HA, cloud/OpenShift
certification, production backup/PITR or old-schema compatibility is claimed.

Infrastructure verification (creates one bounded test Pod, no user credential):
  helm test {{ .Release.Name }} --kube-context "$CONTEXT" -n {{ .Release.Namespace }} --logs --timeout 90s
  node "$CHART/examples/operator.mjs" verify --prepared "$PREPARED" --architecture "$ARCHITECTURE"
Use the prepared CONTEXT and administrator-confirmed amd64/arm64 ARCHITECTURE.
For a safe support summary:
  node "$CHART/examples/operator.mjs" diagnose --prepared "$PREPARED"

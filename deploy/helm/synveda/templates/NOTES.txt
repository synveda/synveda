The normal Job {{ include "synveda.fullname" . }}-install-{{ .Release.Revision }}
performs bounded preflight, advisory-locked migration and optional idempotent
admission. Gateway and worker receive only their own non-owner database Secrets.

  kubectl -n {{ .Release.Namespace }} logs job/{{ include "synveda.fullname" . }}-install-{{ .Release.Revision }} -c database-preflight
  kubectl -n {{ .Release.Namespace }} logs job/{{ include "synveda.fullname" . }}-install-{{ .Release.Revision }} -c migrate

Register exactly {{ .Values.gateway.publicUrl }}/auth/callback with the issuer
in {{ .Values.oidc.existingSecret }}. Its static tenant ID must match
install.tenant.id, or an already-admitted operator-managed tenant.
External login alone grants no workspace membership. Use the existing first
administrator group, then public API invitations and governed grants.

Secrets are mounted files and are never generated or printed by this chart.
After externally rotating credentials or CA files, roll the affected process:

  kubectl -n {{ .Release.Namespace }} rollout restart deployment/{{ include "synveda.fullname" . }} deployment/{{ include "synveda.fullname" . }}-worker

Back up {{ .Values.kms.existingSecret }} separately from the database. Replacing
a KMS Secret is not a key-rotation ceremony. See deploy/helm/synveda/README.md.

Both processes use Recreate: upgrades interrupt service. No gateway HA,
claimed-work shutdown qualification, published image availability, cloud or
OpenShift certification, backup/PITR or old-schema compatibility is claimed.

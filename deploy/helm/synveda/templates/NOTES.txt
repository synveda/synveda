OPERATIONAL LIMITS

  CloudNativePG provides a replicated data plane and the OPS-2 acceptance test
  deletes its primary before repeating a public context request. That is not a
  claim of gateway HA.

  Gateway and core worker remain one replica each and upgrades use `Recreate`.
  Pending login state and cross-process cache invalidation have not passed
  OPS-7's multi-gateway criterion. Only Capture has passed concurrent lease
  fencing; the other core loops have not passed multi-worker acceptance. The
  chart refuses replica keys instead of accepting unsupported availability.

  Worker SIGTERM withdraws readiness, requests cancellation and applies
  `worker.shutdownSeconds` as the hard supervised-task join deadline. Bounded
  idle shutdown is proved. Real process interruption during claimed Capture or
  provider work and subsequent claim recovery remain unproved; a deadline may
  abort unfinished work and provider calls are not exactly once.

  Rotating `{{ .Values.worker.databaseExistingSecret }}` does not restart a
  Pod automatically. Converge the login password and roll the worker as one
  operator action; do not replace the Secret and leave the old process alive.

  Provider credentials and the local KMS key remain Kubernetes Secret
  references. Rendered diagnostics, ordinary APIs and audit rows do not
  contain their values. Key rotation and restore are operator procedures that
  this chart does not automate or prove.

  `deterministic` embeddings are lexical-only. Select `tei` for meaningful
  semantic retrieval. Knowledge index rows retain model and dimension, and a
  model change converges a separately labelled sidecar.

  This chart does not promise zero-downtime gateway upgrades, signed binaries,
  Windows support, an external HSM/customer-managed key integration, SIEM/WORM
  export, or an old-schema translator.

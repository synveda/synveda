WHAT THIS DEPLOYMENT IS AND IS NOT

  HA means the data plane. CloudNativePG runs {{ .Values.postgres.instances }} instances and elects a
  new primary when one is lost; the gateway's pool connects lazily, so a
  failover takes this pod out of the Service and puts it back rather than
  crash-looping it.

  The gateway is one replica and the chart will not render a second. Two
  things in it are process-local and both fail silently: pending logins
  live in memory, so a callback landing on another pod is a 401 for a login
  your IdP completed; and the scope-chain cache is invalidated in-process
  with no TTL, so a hierarchy move handled by one replica leaves the others
  composing against the ancestry the mover left. OPS-7 is the feature that
  fixes both. Until then a gateway restart — including this chart's own
  upgrade, which is a `Recreate` — is a brief outage.

  What is already safe across processes, and needed no work here: the audit
  chain (a row lock on the tenant's chain head), the promotion sweep, the
  lapse expiry sweep, the extraction queue, and console sessions.
{{ if eq .Values.embedder "deterministic" }}
  The embedder is `deterministic`. That is a real choice and a permanent
  one: `record_embeddings` stores the model, the dense leg filters on it,
  and there is no re-embed command — a corpus written this way cannot be
  compared with one written by TEI later. If this deployment will hold a
  corpus anybody searches, `tei` is the value you want, before the first
  record.

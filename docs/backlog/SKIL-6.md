# SKIL-6: Verified procedure improvement candidates

## Problem and evidence

Immutable Skill versions/bindings, usage evidence, ContextRun feedback and
governed Knowledge procedures exist. They do not provide an outcome-to-proposal
learning path. Advertisement/delivery is not execution and a model's assertion
that tests passed is not authenticated verification. See the
[implementation matrix](MEM-8.md#scope).

## Scope

Small deterministic or human-supplied procedure improvements bound to exact
Skill/procedure/context revisions, outcome identity, task/environment applicability,
evidence class and evaluation case. Deduplicate exact evidence processing while
preserving contradictory feedback. Review old/new content through VedaFlow.

## Non-goals

No perpetual reflection loop, self-activation, causal-success claim from inclusion,
mandatory model or private reasoning collection. Review cannot replace quality
qualification, and held-out answers cannot enter candidate generation.

## Architecture seam

Reuse existing extraction/candidate machinery and typed Knowledge/Skill effects.
MEM-8 lineage and source authorization govern every derivative and destination;
private Session content cannot become broader-scope procedure evidence. Preserve
immutable versions, normal approval/apply and explicit binding rollback.

## Acceptance criteria

Verified outcomes produce precisely cited small candidates; unsupported claims
remain unverified. Replayed evidence creates no duplicate. Revoked/forgotten
sources invalidate dependent proposals. Poisoned instructions never bypass
review. Freeze candidate/configuration and held-out variants before qualification.

## Required tests

Public-API procedure-learning tests on ordinary-role PostgreSQL, exact evidence
idempotency, source removal, cross-scope disclosure, fabricated verification and
contradictory feedback. Existing Skill/Capture/context tests remain intact;
required failed quality gates keep a candidate unqualified.

## Rollout and rollback

Keep generation opt-in and review-only. Do not distribute or activate a new
version automatically. Rollback uses existing immutable version/binding commands.

## Dependencies

MEM-8 is a hard implementation gate; SKIL-5 owns authentic usage reporting.
No outcome-learning code is changed at the inspection checkpoint. Next: after
source invalidation, accept the bounded outcome evidence/identity contract and
implement one human-supplied candidate path with no model dependency.
